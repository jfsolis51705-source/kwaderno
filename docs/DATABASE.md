# Database

PostgreSQL 16. Source of truth: `src/db/schema.ts`. Migrations: `drizzle/` (generated by `npm run db:generate`, applied by `npm run db:migrate`).

## Conventions
- **IDs**: UUID (`gen_random_uuid()`).
- **Money**: `bigint` centavos (`*_centavos`). Never floats.
- **Quantities**: `numeric(14,3)` in the product's own unit (allows per-kilo / tingi goods).
- **Timestamps**: `timestamptz`; reporting days are computed in the store's `timezone` (default `Asia/Manila`).
- **Soft delete**: `deleted_at` on users, stores, categories, suppliers, customers; `archived_at` on products. Financial and stock ledgers are **append-only** — never deleted or edited.
- **Isolation**: every store-owned table has `store_id` (FK, `ON DELETE CASCADE`) and indexes leading with `store_id`.

## Tables
| Table | Purpose | Key constraints |
|---|---|---|
| users | Accounts; `is_platform_admin` marks KELSON system owners | unique `lower(email)` |
| sessions | Login sessions (SHA-256 of token only) | unique `token_hash` |
| stores | Store profile, timezone, `allow_negative_stock`, GPS `latitude`/`longitude`, `pilot_merchant_id` | lat/lng in range and set together; a pilot pin can be claimed by only one store |
| pilot_merchants | **Platform-level** list of field-surveyed pilot stores (map pins + survey tabs). Holds personal data (owner name, contact number); **no GCash numbers, wallets or payouts** | unique `external_key`; readable only by `users.is_platform_admin` |
| store_members | User ↔ store with role (owner/manager/staff) & status | unique (store, user) |
| store_counters | Per-store sequences (e.g. sale numbers) without `MAX()+1` races | unique (store, name) |
| categories | Product categories | unique (store, lower(name)) |
| products | Catalog: SKU, brand, unit, packaging, cost/price (centavos), reorder threshold, image | unique (store, lower(sku)); price ≥ 0; pack pair check |
| product_barcodes | Many barcodes per product | **unique (store, barcode)** — one product per barcode per store; other stores may reuse |
| inventory_balances | Current stock per product (+ `version`) | PK product_id; locked `FOR UPDATE` on every movement |
| inventory_transactions | Append-only stock ledger: type, delta, balance_after, cost, reason, user, reference | delta ≠ 0; unique (store, idempotency_key, product) |
| suppliers | Suppliers per store | unique (store, lower(name)) |
| purchases / purchase_items | Stock-in documents and lines | unique idempotency key; **unique receipt_id** |
| receipts / receipt_items | Uploaded receipt, raw AI output (never overwritten), extracted vs merchant-reviewed values, status | status enum: uploaded, queued, processing, pending_review, confirmed, failed, rejected |
| customers | Customer + running `balance_centavos` | |
| customer_ledger | Append-only utang ledger (credit_sale, payment, adjustment, sale_void) with balance_after | |
| sales / sale_items | Sale header (+ `occurred_at` for offline) and lines with price & cost snapshot | total = subtotal − discount; qty > 0; unique (store, sale_no); unique idempotency key |
| payments | Cash / GCash (recorded, not verified) / credit | amount > 0; unique idempotency key |
| audit_logs | Who did what, before/after JSON | |
| product_expiries | Tracked batches: expiry date, optional qty, product photo + label photo (private), status, clear reason, link to the `expired` stock movement | qty > 0 if set; index (store, status, date) |
| devices | Client devices per store/user (offline sync) | unique (store, client_device_id) |
| sync_operations | Offline operations received from devices; status received/applied/conflict/failed | **unique (store, operation_id)** |

## Packaging variants
Each packaging format is its **own product with its own stock**. A "Box of 12 sachets" product has
`pack_child_id = <sachet product>` and `pack_quantity = 12`. Opening a box is an explicit pair of
movements (`repack_out` on the box, `repack_in` of 12 on the sachet) — the system never assumes a box
and a sachet share inventory units.

## Relationships (simplified)
```
users ─< store_members >─ stores ─< products ─< product_barcodes
                                  │          └─1 inventory_balances
                                  │          └─< inventory_transactions
                                  ├─< customers ─< customer_ledger
                                  ├─< sales ─< sale_items          payments >─ sales/customers
                                  ├─< receipts ─< receipt_items ─ purchase_items >─ purchases >─ suppliers
                                  ├─< devices ─< sync_operations
                                  └─< audit_logs
```

## Pilot merchant data (privacy)
- Source files (Google My Maps KML + the survey workbook) live in `data/private/`, which is **git-ignored**.
- `npm run pilot:normalize` merges them into `data/private/pilot-merchants.json`, keeping only: store name, address, barangay, city,
  coordinates, business type, map layer/surveyor, signed/registered/retention status, survey date, owner name, contact mobile.
  GCash numbers, crypto wallets/networks/QR links, payout amounts/dates/references, photo links and free-text remarks are dropped.
- `npm run pilot:import` upserts them (idempotent) and links any store whose GPS position is within **50 m** of an unclaimed pin.
- Merchants only ever see the matched pilot **store name**; owner/contact fields are returned only by the platform-admin endpoint.
